# Weapon Detection

A weapon detection model built by fine-tuning an [Ultralytics YOLO](https://docs.ultralytics.com/) detector on real images and on synthetic images generated by a LoRA fine-tuned **FLUX.1-dev** diffusion model. The synthetic images are used to reduce false positives.

`best_inf_2.mp4` in the repo root is a demo video of the detector's output.

## Goal

Detect weapons in camera footage accurately **without raising alarms on harmless objects**.

A detector trained only on images of guns learns to associate the *pose* with the weapon. It sees "a person with arms extended and both hands together at chest height" and predicts a gun, even when the person is holding a phone, a wallet or a TV remote.

The project solves this in two parts:

1. **A weapon detector:** a YOLO model trained and fine-tuned at 1024 px on a weapon dataset.
2. **A synthetic hard-negative generator:** FLUX.1-dev fine-tuned with LoRA on CCTV-style images of a person in a shooting stance. The adapted model generates images of people in the *same weapon-like pose and scene, holding non-weapon objects*. These images are added to the training data so the detector learns that the pose alone is not a weapon.

## How it works

### Stage 1: Base detector training

**File:** `weapon_detection/training.py`

Trains from pretrained `yolov8m.pt` weights on the weapon dataset defined in `data/data.yaml` (Ultralytics YOLO format).

| Setting | Value |
|---|---|
| Base weights | `yolov8m.pt` |
| Image size | 1024 |
| Epochs | 100 |
| Batch | 32 |
| Optimizer | SGD, `lr0=0.01`, `lrf=0.0001`, `momentum=0.937` |
| Weight decay | 0.0005 |
| Warmup | 5 epochs, `warmup_momentum=0.8`, `warmup_bias_lr=0.1` |
| Output | `runs/weapons_jupyter` |

The 1024 px image size keeps small weapons in CCTV frames visible to the model.

### Stage 2: Synthetic data with FLUX + LoRA

**Folder:** `Flux-LoRA-fintune/`, covered in detail in [Synthetic data pipeline](#synthetic-data-pipeline).

1. Collect a small seed set of real images in the target style (`seed_cctv_pose/images`).
2. Fine-tune **FLUX.1-dev** with a **LoRA** adapter so it learns the camera style, scene and body pose.
3. Prompt the adapted model for the same pose and scene holding a harmless object (phone, wallet, remote, umbrella and more), with weapon terms in the negative prompt.
4. Check the generated images and add them to the YOLO training dataset.

### Stage 3: Fine-tuning on real + synthetic data

**File:** `weapon_detection/finetune2.py`

Continues training from the fine-tuned checkpoint `runs/finetune/weights/best.pt` on the extended dataset with a low learning rate, so the model keeps its weapon knowledge while learning from the new data.

| Setting | Value |
|---|---|
| Starting weights | `runs/finetune/weights/best.pt` |
| Image size | 1024 |
| Epochs | 70 |
| Batch | 16 |
| Optimizer | SGD, `lr0=0.0003`, `lrf=0.0003` |
| Weight decay | 0.0009 |
| Dropout | 0.15 |
| Warmup | 5 epochs, `warmup_momentum=0.85`, `warmup_bias_lr=0.05` |
| Output | `runs/finetune_new` |

### Stage 4: Inference

| Script | Input | Output | Details |
|---|---|---|---|
| `weapon_detection/inference_video.py` | Local video file (`test/VID_1.mp4`) | Annotated video on disk | Corner-style boxes labelled `Weapon <conf>`. `conf=0.4`, `iou=0.2`, `imgsz=1024`. Tries `avc1`/`mp4v` MP4, then `XVID`/`MJPG` AVI until a working codec is found. |
| `inference_video.py` (root) | YouTube URL | Live OpenCV window | Uses `yt-dlp` to resolve a ≤720p MP4 stream without downloading it. `conf=0.4`, `iou=0.45`, `imgsz=1024`, optional frame `skip`. Press `q` to quit. |
| `inference_image.py` (root) | Single image (`IMG_1.jpg`) | Annotated image (`out.jpg`) | Letterboxes the image to 1024 px, runs the model, maps boxes back to the original image and draws labelled boxes. |

Both video scripts use **overlay smoothing**: if the model misses the weapon for a few frames, the last boxes stay on screen for `OVERLAY_FRAMES` frames (5 in the offline script, 3 in the live one). This stops the boxes flickering.

## Synthetic data pipeline

There are three ways to train the LoRA. All use `black-forest-labs/FLUX.1-dev` from Hugging Face and training scripts from the [huggingface/diffusers](https://github.com/huggingface/diffusers) repo.

```
          ┌────────────────────┐
          │  Seed images       │  real CCTV-style photos of the target
          │  (+ captions)      │  pose / scene / lighting
          └─────────┬──────────┘
                    │
     ┌──────────────┼───────────────────────────────┐
     ▼              ▼                               ▼
 Image-only     Image + captions               QLoRA route
 LoRA           LoRA                           (precomputed embeddings)
 finetune_      create_ymal.py →               prepare_embeddings.py →
 images.py      finetune.py                    finetune_flux.py
     │              │                               │
     └──────────────┴──────────────┬────────────────┘
                                   ▼
                    pytorch_lora_weights.safetensors
                                   │
                                   ▼
                 gen.py: FLUX.1-dev + LoRA + prompts
                 (pose/scene + benign object, weapon terms as negatives)
                                   │
                                   ▼
                   Image check → YOLO training dataset
```

### Step 0: Environment and access

- NVIDIA GPU with ≥30 GB VRAM recommended, CUDA 11.8+, Python 3.10–3.11.
- Install the dependencies:
  ```bash
  pip install -U transformers torch accelerate bitsandbytes datasets safetensors pillow sentencepiece peft
  ```
  ```bash
  python -m pip install -U "git+https://github.com/huggingface/diffusers.git"
  ```
  ```bash
  git clone https://github.com/huggingface/diffusers
  ```
- FLUX.1-dev is a gated model. Accept its terms at <https://huggingface.co/black-forest-labs/FLUX.1-dev>, then log in:
  ```bash
  huggingface-cli login
  ```
- Run `testflux.py` to confirm access. It generates `flux-test.png` ("a cat holding a sign that says hello world") with `enable_model_cpu_offload()` to save VRAM.

### Step 1: Seed data

A small folder of real images showing what the generator should learn: a person in a shooting stance in a CCTV-style scene (`seed_cctv_pose`).

Choose the training mode:

- **Images only:** the LoRA learns the look (pose, scene, background, camera style).
- **Images + captions:** the LoRA links specific words to specific content in the image. Each caption describes the image the way you would prompt the model to generate it.

### Step 2a: Image-only LoRA (`Flux_finetune_LoRA_imageonly/finetune_images.py`)

1. Uses `bf16` mixed precision if the GPU supports it, otherwise `fp16`.
2. Writes a single-GPU `accelerate_config.yaml`.
3. Launches diffusers' `examples/advanced_diffusion_training/train_dreambooth_lora_flux_advanced.py` with:
   - `--instance_data_dir seed_cctv_pose/images`, `--instance_prompt "cctv pose subject"`
   - `--resolution 512`, `--train_batch_size 1`, `--gradient_accumulation_steps 4`, `--gradient_checkpointing`
   - `--learning_rate 1e-4`, constant schedule, no warmup
   - `--rank 4`, LoRA on the attention layers `attn.to_k,attn.to_q,attn.to_v,attn.to_out.0`
   - `--max_train_steps 2000`, checkpoint every 200 steps, `--seed 42`
   - `--guidance_scale 1`, TensorBoard logging
4. Saves the LoRA to `seed_cctv_pose/flux_pose_lora/`.

### Step 2b: Image + caption LoRA (`Flux_finetune_LoRA_imagewcaptions/`)

1. Create `captions.csv`:
   ```csv
   filepath,caption
   images/IMG_1.jpg,"Caption_1"
   images/IMG_2.jpg,"Caption_2"
   ```
2. Run `create_ymal.py` to convert the CSV into `captions.yaml` and place it in the images folder.
3. Run `finetune.py`. It uses the same launcher and hyperparameters as 2a in dataset mode (`--dataset_name seed_cctv_pose/images --image_column image --caption_column text`), so each image is trained with its own caption.

### Step 2c: QLoRA route with precomputed embeddings (`Flux-LoRA-fintune/` root)

A lower-memory route based on diffusers' `examples/research_projects/flux_lora_quantization`.

1. **`prepare_embeddings.py`**
   - Clones `huggingface/diffusers` if it is missing and installs the research project's `requirements.txt`.
   - Runs `compute_embeddings.py` on `IMAGES_DIR` and `CAPTIONS_CSV` and saves the text embeddings to `embeddings_cctv.parquet`.
   - Precomputing the embeddings means the text encoders don't need to be loaded during training.
2. **`finetune_flux.py`**
   - Checks the paths and that `accelerate` is installed, then launches `train_dreambooth_lora_flux_miniature.py` with `--data_df_path embeddings_cctv.parquet`.
   - Settings: `768×512`, batch 1, gradient accumulation 4, `lr 1e-4` constant, `rank 8`, `1500` steps, `bf16`, `--use_8bit_adam`, `--gradient_checkpointing`.
   - Saves the LoRA to `./lora_cctvParkingPose/pytorch_lora_weights.safetensors`.

### Step 3: Generate hard negatives (`Flux-LoRA-fintune/gen.py`)

- Loads FLUX.1-dev (fp16, CPU offload) with the `lora_cctvParkingPose` LoRA.
- **Base prompt:**
  > *hooded person, feet apart, arms extended with a two-hand grip at chest height, underground parking garage at night, warm sodium lights, CCTV scanlines and HUD, cctvParkingPose*

  `cctvParkingPose` is the trigger token for the LoRA.
- **Objects placed in the grip:** smartphone, wallet, sunglasses case, power bank with USB cable, compact camera, TV remote, folded umbrella, deodorant spray can, key fob with dangling keys, small water bottle, vape pen, hairbrush.
- **Negative prompt:** `gun, pistol, rifle, barrel, trigger, muzzle, knife, blood, watermark, text artifact`
- **Settings:** 512×768 (W×H), `guidance_scale 3.5`, 34 steps, fixed seed per object (`100+i`) for reproducible results.
- **Output:** `gen/cctv_XX_<object>.png`

The result is a set of images that match the frames that trigger false positives (same stance, lighting and camera look) but contain no weapon.

The `Synthetic_image_gen_Flux/*/gen.py` scripts are templates for the same step: fill in `CAPTIONS` (prompts) and `NEG`, point `LORA_DIR` at a checkpoint, and they generate 720×480 images with 28 steps.

### Step 4: Add to the training set

Check every generated image to make sure the training data is good quality, then add the images to the YOLO training dataset and run Stage 3.

## Quickstart

### Run the detector on a video

```bash
cd weapon_detection
```
```bash
pip install -r requirements.txt
```

Set `source`, `output`, `weights`, `_conf`, `_iou`, `_imgsz` and `device` at the top of `inference_video.py`, then run:

```bash
python inference_video.py
```

Keep the image size at 1024 for best results.

### Run on a YouTube stream

```bash
pip install ultralytics opencv-python yt-dlp torch
```

Set `url` and `weights` at the top of the root `inference_video.py`, then run:

```bash
python inference_video.py
```

### Train and fine-tune

```bash
cd weapon_detection
```
```bash
python training.py
```
```bash
python finetune2.py
```

Both read `data/data.yaml`. `finetune2.py` starts from `runs/finetune/weights/best.pt`.

### Generate synthetic images

Run `testflux.py`, train a LoRA with one of the routes in [Synthetic data pipeline](#synthetic-data-pipeline), then run `gen.py`.
